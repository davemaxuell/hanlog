# Client launch audit — 16 November 2026

## Reproduced and repaired

- A generated or rotated recovery key disappeared when its page unmounted during client navigation. The root layout now owns an in-memory recovery dialog. Browser navigation preserves the key, the existing reload warning remains, and explicit acknowledgment dismisses it. Keys are never written to browser storage. Restore adopts the returned profile immediately while the dialog preserves its replacement key.
- A second browser tab could change the cookie's profile or role while the first tab continued to display the old identity and private draft. Focus, visibility, persisted-page resume, and a credential-free storage notification now revalidate the session. Concurrent checks are coalesced. Announced changes immediately hide private controls; requests that finish after a newer identity update are ignored. Identity/role changes remount private content. A change arriving during initial lookup schedules another lookup rather than being lost.
- A profile update completing after navigation could update the persistent session and fetch points. Profile/onboarding mutations now guard page lifetime. Deletion clears the cached session, and recovery-settings 401 responses use the normal expiration path.
- Changing a `useApi` resource briefly exposed the previous response and controls. Data and loading/error states now follow request inputs while same-resource refreshes preserve their data. Late old requests cannot overwrite newer results.
- Earlier history pages appeared under a newly selected mission, and a reported challenge's success state survived navigation into another challenge. Both stateful views now reset at their resource boundary.
- Mission filters disappeared when returning from a mission. Filters now live in the URL, with browser-history subscriptions; filter edits replace the current entry without a server request. Unit tests reset their browser history between cases.
- Browser `MediaRecorder.stop()` exceptions left the microphone open. Stop now releases every track even on failure. A distinct finishing state prevents starting another recording while final data is pending; a missing final event fails after five seconds. Meter-read failures no longer break capture. Pending microphone requests can be cancelled, and a late permission grant is released.
- Arbitrary-size uploads were read and decoded before validation, and conversion copied all decoded audio before trimming. Encoded input is rejected above the existing 4,000,000-byte peer-media limit before reading; the picker retains an existing recording when rejecting a large replacement. Only the required 20-second channel slices are copied. Upload copy explicitly explains the size limit and first-20-seconds behavior. A failed submission retains the exact blob for retry.

## Evidence

Failing tests were observed for the defects above before repair. Additional tests verify cancelled late permission grants and exact-blob network retries. Focused account/profile/session/recorder tests passed (34 tests); resource/history/library/challenge tests passed (20 tests). The full UI run passed 123 of 124 tests before discovering that a newly durable URL filter crossed test cases. After adding test history isolation, both affected saved-mission and challenge suites passed (16 tests). TypeScript and targeted ESLint passed. Root owns the final integrated check.

`tests/e2e/account.spec.ts` adds browser Back, Escape, and cancelled reload coverage while an unsaved key is visible. `tests/e2e/recovery.spec.ts` adds real same-context tab role synchronization, stale draft removal, and expiration on focus. Both files disable traces, screenshots, and video; keys stay in memory and boolean comparisons avoid credential assertion diffs. These browser cases are prepared for the root-run production build; no browser runner or application server was started in this lane.

## Boundaries

No backend contract, dependency, paid scoring call, deployment, production data, or real credential changed. The original navy/sky/cream/pink design and bundled fonts remain. Browser native audio decoding may still allocate its own full decode buffer for an accepted compressed file; the encoded-input guard and bounded channel copies reduce exposure but do not establish a strict native-memory bound. Physical iPhone/Android capture and permission behavior still require device testing. A browser restart or an explicitly accepted reload can discard an unacknowledged in-memory key; the browser warning communicates that boundary without persisting a credential.

## Integrated browser follow-up

The production browser run exposed a redirect race after successful deletion: Me requested the home page, then the provider's ordinary unauthenticated redirect replaced it with onboarding. Logout had the same latent race. Two exact-destination unit regressions reproduced both competing navigations. Deliberate exits now clear the session and record their destination in one provider action; ordinary guards resume once that destination is reached. The affected profile/recovery/session suites passed 26 tests after the fix.

Browser harness follow-ups preserve the behavior checks: cancelled reload is triggered with `window.location.reload()` without awaiting a navigation that the user cancelled, and the asynchronous role radio uses a click followed by a retrying checked assertion. The cross-tab expiration case uses the real Delete UI to exercise its storage notification; raw API deletion bypasses that notification, and headless `bringToFront()` does not reliably dispatch focus. Explicit unit focus events cover the fallback and its onboarding redirect.

Credential-test workers also set `PLAYWRIGHT_NO_COPY_PROMPT=1` to suppress automatic failure copy-prompts. That setting alone does not suppress the separate DOM context produced by failed locator/page matchers. Every assertion while a recovery key may be displayed or entered now polls a boolean instead, including URL, focus, visibility, acknowledgment, dialog dismissal, and invalid-key feedback checks. Root owns rerunning the compiled browser suite and removing any earlier synthetic failure artifacts; these settings are safeguards, not proof that every possible framework failure artifact is credential-free.
