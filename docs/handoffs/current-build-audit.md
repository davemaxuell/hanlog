# Current build audit — 16 November 2026

This audit follows the [launch upgrade](launch-upgrade.md). Three independent reviewers examined accounts/progress, client behavior, and community/media; the integrator examined scoring boundaries and persistence, combined the repairs, and owns release verification. The PowerPoint-based navy, sky, cream, and pink design remains unchanged.

## Reproduced defects repaired

- **Session revocation at the write boundary.** A request authenticated before logout could finish afterward and still edit/delete a profile, save a mission, publish community content, rate/report, or persist a score. Mutations now carry the authenticated session version and recheck it while locking the user in their transaction. Scoring also checks before reserving its allowance. Work already authorized under that lock completes before logout; requests reaching it afterward fail. The server rechecks current roles for role-dependent writes.
- **Deletion and daily limits.** Profile deletion now takes an exclusive user lock before detaching scoring identifiers, preventing a late reservation from retaining a deleted profile ID. Migration 007 stores daily profile-creation counters independently of profiles, so deleting a profile no longer resets that network's allowance. Counters expire by Korea date. The migration backfills surviving profiles; earlier deleted creations cannot be reconstructed.
- **Scoring input and atomic persistence.** The scoring endpoint now rejects incomplete or ambiguous PCM WAV containers, duplicate format/data chunks, inconsistent byte rates, and partial frames before quota reservation. A successful score, points, and the reservation's scored outcome commit together. Failed bookkeeping rolls back the score and points; terminal reservation outcomes cannot be overwritten by a later failure handler. Cleanup retains recent pending reservations for one hour across Korea midnight so a valid in-flight score can still commit. Provider calls remain outside the database transaction, and a provider call already sent may still incur cost if a session is revoked before its result arrives.
- **Community visibility and moderation.** Personally hidden challenges apply consistently to response endpoints. An operator can no longer accidentally unhide a recording after its report disappears during review. Parent/response and cleanup/user lock ordering now match deletion. Invalid year-zero cursors return 400, and speaking videos without audio return 415.
- **Recovery keys and tab identity.** Unsaved recovery keys remain in a root-level, memory-only dialog during client navigation and browser Back. Explicit acknowledgment is required; reload retains its browser warning. Other tabs revalidate identity/role on credential-free change notifications and focus. Stale requests cannot restore an earlier identity, balance, resource response, or private draft. Deliberate deletion/sign-out now clears local identity and chooses its destination together, preventing the automatic session guard from replacing the intended navigation.
- **Practice navigation and recording.** Mission filters survive return navigation; history/challenge state resets for a new resource. Recorder failures and cancellation release microphone tracks, stop completion has a timeout, and another recording cannot begin while final data is pending. Uploads exceeding 4,000,000 bytes are rejected before reading; conversion copies only the first 20 seconds. Submission retries preserve the recorded blob.

Each repair has a regression that failed before its implementation. Detailed triggers, ownership, and scoped results are in [accounts](audit-accounts-2026-11-16.md), [client](client-launch-audit.md), and [community/media](current-audit-peer-media.md).

The account reviewer separately passed all **17 real PostgreSQL 17.11 concurrency cases** in a disposable, loopback-only container, which was removed afterward.

The production build passed. Its final Chromium run passed **42 phone/desktop browser tests**, with six deliberately skipped duplicate phone accessibility cases; the desktop accessibility checks ran and passed. Coverage includes recovery-key Back/reload warnings, restore/rotation/export/deletion, cross-tab identity changes and deletion notifications, solo scoring with synthetic input, two-browser peer exchanges, voice/video capture, microphone fallback, keyboard operation, responsive widths, and security headers/origin checks. Credential-bearing checks disable recording and automatic DOM captures and use boolean assertions while keys are visible or entered. Native focus fallback is covered by event-driven component tests; headless tab activation is not evidence of physical-device focus behavior.

Browser bundles and tracked source passed the secret check. Server trace inspection found **zero private paths** across 48 traces. The dependency audit reports **zero known vulnerabilities**. No paid scoring calls were made for this audit. Release and hosted verification identifiers will be recorded after deployment.

Apply additive migration **007** before deploying its consumers. Preserve the production session secret. The release keeps the existing real OpenAI configuration and production spending caps.

## Evidence limits and release follow-up

- Automated phone checks use Chromium emulation and synthetic media. Physical iPhone/Android capture, playback, interruption, and permission testing remain open in the [device checklist](../device-check.md).
- Korean content needs native-speaker review. Pronunciation quality, consistency, learner calibration, and the acceptance evaluation still need consented learner samples and a small separately controlled live-call budget. Existing hosted AI compatibility evidence is documented in [QA](qa.md); this audit adds no new AI-quality evidence.
- Compressed audio within the upload-size cap can still make a browser allocate a larger native decode buffer. The bounded input and channel copies do not establish a strict decoder-memory limit. Parser fuzzing and real-device codec coverage were not performed.
- Recovery depends on possession of the current key or a signed-in browser. Accepting a reload or closing the browser can discard an unsaved memory-only key. Keys are intentionally not persisted to browser storage.
- The audit does not establish exactly-once provider billing after a network interruption, a consistent database snapshot for an export during concurrent writes, or recovery of already-deleted historical quota events. It is evidence of the tested behavior, not a guarantee that no defect remains.
